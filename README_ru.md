# JazzNote

Second Brain — локальное приложение для заметок в Markdown с inline live-preview в стиле Obsidian.

Стек: Electron + React + TypeScript на базе CodeMirror 6. Заметки — обычные `.md`-файлы на диске: без привязки к формату, без базы данных, всё твоё.

Вдохновлено [Obsidian](https://obsidian.md): хранилище plain-Markdown с inline live-preview, знакомое пользователям Obsidian.

**Статус:** ранний этап, уже пригоден для ежедневных заметок.

## Возможности

### Редактирование
- **Inline live-preview** — `# Заголовок`, `**жирный**`, ссылки и списки рендерятся прямо в редакторе (как в Obsidian)
- **Подсветка кода** — JS/TS, Python, Go, Rust, Ruby, Swift, Shell, TOML, Dockerfile, HTML, CSS, JSON, YAML, Markdown, Java, C/C++, PHP, SQL, XML
- **Undo/redo для каждой заметки** — стек отмены наполняется из git-истории (до 500 версий) и пополняется вживую, поэтому `Ctrl/Cmd+Z` может откатить заметку к самой первой сохранённой версии; тост со счётчиком шагов
- **Горячие клавиши** — `Ctrl/Cmd+S` сохранить, `Ctrl/Cmd+Z` отмена, `Shift+Ctrl/Cmd+Z` / `Ctrl/Cmd+Y` повтор

### Заметки
- **Обычные Markdown-файлы** в папке-хранилище (папку можно выбрать в настройках; по умолчанию `~/Documents/jazz-notes`, создаётся автоматически)
- **Полный CRUD** — создание, редактирование, удаление заметок и папок; **вложенные папки** любой глубины
- **Контекстное меню (ПКМ)** — на заметке: переименовать, переместить в папку, изменить дату/цвет, удалить; на папке: переименовать, переместить (в другую папку или в корень), удалить
- **Новая заметка — в выбранную папку** — когда в сайдбаре активна папка, новые заметки создаются внутри неё; новая папка тоже создаётся внутри выбранной. Корень хранилища выбирается в сайдбаре (назван по папке хранилища), поэтому заметки и папки можно создавать и в самом корне
- **Поиск** — полнотекстовый по заголовку и тексту, без учёта регистра
- **Фильтры** — Все / Сегодня / Завтра / Неделя / Позже / Без срока
- **Сортировка** — по дате изменения / создания / срока
- **Метаданные** — заголовок, срок, цвет, авто-ID, время создания/изменения; цвет заметки подсвечивает карточку в списке и **фон/текст в редакторе**; **pill-бейдж с папкой** отмечает заметки внутри папок
- **Обратный отсчёт до следующего срока** — всегда виден вверху главной страницы, тикает в реальном времени; можно скрыть (крестик на плашке или тумблер в настройках), выбор запоминается

### Надёжность
- **Отложенное автосохранение** (400 мс на текст, сразу при выходе из заметки) с живым индикатором статуса (idle → dirty → saving → saved/error)
- **Слежение за файлами** (chokidar) — внешние правки подхватываются автоматически
- **Один экземпляр приложения**, изолированный preload-мост, без меню
- **Unit-тесты (Vitest) + CI** — GitHub Actions запускает тесты и сборку на каждый push

### Синхронизация и версии
- **Хранилище на Git** — папка с заметками является git-репозиторием; каждое автосохранение становится коммитом, ничего не теряется
- **Системный git не нужен** — все git-операции выполняются встроенным JS-движком (isomorphic-git) внутри приложения, так что оно работает на любом устройстве без установки чего-либо
- **История версий заметки** — кнопка истории в редакторе показывает прошлые версии; любую можно предпросмотреть и восстановить (восстановление — новый коммит, история не переписывается)
- **Движок синхронизации** — push/pull/merge против git-remote (URL, логин и токен настраиваются в настройках). Неконфликтные изменения мержатся автоматически. Remote указываешь сам (например, репозиторий на GitHub); свой vault-сервер JazzNote пока не хостит — см. [ROADMAP](ROADMAP_ru.md) (issue #8)
- **Простое подключение устройств** — URL, логин и токен можно передать как **QR-код** или строку; на другом устройстве QR сканируется камерой или строка вставляется вручную
- **Индикатор синхронизации** — точка в правом верхнем углу: зелёная = синхронизировано, жёлтая = сервер недоступен, красная = ошибка, оранжевая = конфликты; клик — подробности, кнопка ручной синхронизации и разрешение конфликтов
- **Разрешение конфликтов** — если файл менялся с обеих сторон, для каждого файла можно выбрать локальную или серверную версию (с предпросмотром) и применить

### Внешний вид
- **3 палитры** — TokyoNight, Everforest, Catppuccin — каждая в **тёмной и светлой** версии
- **5 шрифтов Monaspace** (Argon, Neon, Krypton, Xenon, Radon) + Nerd Font для иконок
- Пикеры **цвета** и **даты** для заметок; просроченные сроки подсвечиваются красным
- **Двуязычный интерфейс** — Русский / English, переключается в настройках и сохраняется

## Как хранятся заметки

Заметки — обычные `.md`-файлы в хранилище, при желании во вложенных папках. Каждый файл несёт небольшой frontmatter-блок:

```
~/Documents/jazz-notes/
├── 00001.md
└── subfolder/
    └── 00002.md
```

```markdown
---
title: "Моя заметка"
id: "00001"
due: "2026-08-06T14:30"
color: "blue"
created: "2026-08-05T00:00:00.000Z"
updated: "2026-08-06T00:00:00.000Z"
---

# Моя заметка
Текст заметки…
```

Поддерживаемые ключи frontmatter: `title`, `id`, `priority` (0–4), `due`, `color`, `created`, `updated`, `tags`. Парсер обрабатывает значения в кавычках с экранированием, скалярные значения без кавычек и строки `---` внутри текста.

Настройки приложения (палитра, тема, язык, шрифт, путь к хранилищу) хранятся в `localStorage` под ключом `jazz-settings`.

## Веб-версия (браузер)

Тот же интерфейс рендерера работает в браузере против того же хранилища: его обслуживает небольшой Node.js-сервер (`web/`), переиспользующий git- и save-логику приложения.

Сборка и локальный запуск:

```bash
npm run web:build   # собирает клиент (web/dist) и бандл сервера (web/dist-server/server.js)
npm run web:dev     # vite dev-сервер для браузерного UI
npm run web:preview # предпросмотр собранного клиента
```

Сервер (запуск `node web/dist-server/server.js`) отдаёт хранилище через тот же API `jazz`, что и десктопное приложение. Переменные окружения:

| Переменная | По умолчанию | Назначение |
|------------|-------------|------------|
| `JAZZ_VAULT` | `~/jazz-notes` | Путь к хранилищу заметок |
| `PORT` | `3180` | HTTP-порт |
| `JAZZ_WEB_ROOT` | `web/dist` | Корень статического клиента |

### Приём заметок по HTTP

`POST /api/note` создаёт одну или несколько заметок из обычного JSON — удобно для телефона/curl/автоматизации. Требуется заголовок `X-Auth-Token` (переменная окружения `JAZZ_NOTE_TOKEN`); если токен не задан, endpoint отключён.

```bash
curl -H 'X-Auth-Token: ваш-токен' -H 'Content-Type: application/json' \
  -d '{"title":"Быстрая заметка","text":"тело","folder":"inbox","due":"2026-08-15","color":"red","priority":2,"tags":["работа"]}' \
  https://notes.example.com/api/note
```

Можно передать и массив объектов. Допустимые поля: `title`, `text`, `folder`, `due`, `color`, `priority`, `tags`. Заметки проходят через тот же saver, что и приложение: ID назначаются автоматически, frontmatter генерируется, автосохранение коммитится.

### Развёртывание на сервере

Каждый релиз включает самодостаточный серверный бандл — `jazz-note-server-<версия>.tar.gz` (на странице [Releases](https://github.com/jazz-crab/jazz-note/releases)). Для него нужен **только Node.js**; все остальные зависимости вкомпилированы в `server.js`. В бандле: `server.js`, статический клиент (`dist/`) и `install.sh`, который ставит всё на хосте с systemd:

```bash
tar -xzf jazz-note-server-<версия>.tar.gz
cd jazz-note-server-<версия>
./install.sh
```

`install.sh` ставит Node.js через apt (если нет), создаёт хранилище (`~/jazz-notes`), пишет env-файл со сгенерированным `JAZZ_NOTE_TOKEN` и регистрирует systemd-сервис `jazz-note-server`. Повторный запуск — это обновление: существующие хранилище и env-файл сохраняются.

Ручной запуск (любой хост с Node.js):

```bash
export JAZZ_VAULT=~/jazz-notes
export JAZZ_NOTE_TOKEN=<секрет>
node server.js   # слушает PORT (по умолчанию 3180)
```
